# 自动经验整理与官方宿主适配

2026-10-04。对照官方 `dsh-v0.2.1-alpha.1` 源码提交 `5badb15009ae1756c3afe0ae0cef1faafc290ccc`，并验证 RC2 的公共接口。

## 接入位置

- `session/event` 的 `turn/start`、可见人类/助手消息、工具名及 `turn/end`：只观察新事件，不扫描所有历史会话。只处理正常完成的主会话；忽略子代理、种子、取消、错误、截断和 Dream 自身工具。
- `agent/inbox/claimed` 在官方 `Agent.preStep()` 的 prompt assembly 之前发出：获取当前任务查询。`systemPrompt.context()` 用 agent scope 提供少量已审阅经验，作为 user-role 动态上下文，不改系统规则。
- `Session.requestContext()` / `requestHeader()`：沿用当前会话的实际 provider/model。`ctx.llm.stream()` 执行无工具的短辅助请求，不另读密钥、不绕开宿主 adapter；缺少服务时报告不可用，保留手动工具。

## 默认行为

每轮检查；明确纠正/偏好，或至少两次非 Dream 工具操作且有可见总结时，才尝试整理。模型允许返回空列表。默认每天最多 4 次辅助请求，调用间隔至少 10 分钟，输入最多 12000 字符、输出最多 1200 token，每次最多 3 条经验。普通闲聊跳过。来源文本在进入模型前脱敏，只取有限的可见消息，不取隐藏推理、系统提示和工具参数/结果正文。

自动结果一律 candidate，不调用审阅、规则应用或日记写入。来源序号/引用由插件对照实际观察到的会话消息核验；来源存在只说明读过来源，不代表结论成立。可见时间线列出候选及证据，审阅后才用于自动取回。取回最多 3 条，预算 3000 字符，保留条件和例外，项目隔离；候选/冲突/过期/拒绝经验不注入。

## 可控与恢复

设置页分别提供自动整理和自动取回开关，以及每日次数、最近检查/结果/跳过原因、待审阅数量。控制路由使用官方 authenticated Connection Fetch carrier。整理使用持久化游标和每日预算、原子状态文件及短文件锁，重启/HMR 不重复消费已处理轮次。每次调用先扣预算，Dream 本身不重试；宿主 adapter 的重试策略保持原样。失败/取消显示原因。用户开启下一轮或卸载插件时取消相应整理，不把辅助工作排进用户消息队列。

## 验收

覆盖真实官方事件/消息与 prompt assembly 顺序、无人说触发词的候选创建、普通聊天跳过、去重/重启、预算/冷却、多进程竞争、错误/超时/卸载/新输入取消、来源核验与脱敏、范围和状态过滤。浏览器实际检查中英开关、状态、候选来源/审阅及窄屏。官方 RC2 / alpha 完整注册和 CLI 安装启动另验收。真实 provider 请求与脚本 adapter 分开记录，不用脚本返回值冒充真实服务通过。
