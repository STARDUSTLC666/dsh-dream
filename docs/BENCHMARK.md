# `dsh-dream` 记忆评测与横向对比报告

> **评测日期**：2026-11-27（Windows / Node.js v24.16.0 / Python 3.13.14）
> **评测对象**：`@stardustlc/dsh-dream`（改造前 `v0.19.3` 基线 vs DeepSeek Harness `0.2.2-rc.3` 深度适配 + 零依赖混合 BM25F 优化版）
> **复现脚本**：[`scripts/benchmark-memory.mjs`](../scripts/benchmark-memory.mjs)

## 0. 评测声明与口径边界（请先读）

为了避免“基准刷分”或跨口径误导，本报告严格区分数据来源与实验边界：

1. **本机同机无并发串行实跑 vs 上游公开快照**：
   - `dsh-dream`（`v0.19.3` 与优化版）、`Okapi BM25`、`Char-2gram Cosine` 以及 **灵枢 Lingshu (`@furongjun1999/dsh-memory`)** 在 `locomo-zh-500` 与 `memory-bench-1000` 上的成绩与耗时均为**本机同环境单次串行无并发直接实测**（灵枢在临时目录构建 `MdCGOS`、按其官方口径启用 `unlock_global_cap` + `install_read_cache`，在 `locomo-zh-500` 使用官方 `bench_locomo_zh_public.py` 的 `jaccard` 口径，在短条目 `memory-bench-1000` 保持其默认生产评分口径，不改动其仓库文件）。
   - `bench6-100-zh-en` 中的竞品数据引用自 `dsh-memory/data/benchmarks/bench6-100-zh-en/results_v1.0.json`：其中灵枢各变体与 `vector_rag`（12/12 含逐题明细的语言臂）已通过 `run_bench.py --demo` 重算逐位核验；`letta_archival`、`letta_agent`、`mem0`、`graphiti`、`graphrag`（10 个语言臂）上游仅提供汇总 `summary`（`run_bench.py` 显式标记 `SKIP`），未在本地重跑外部云 API / LLM 嵌入服务。
2. **语料入库与计时口径**：
   - `bench6-100-zh-en` 同时报告两条诚实轨道：**`(raw-en)`** 仅入库原始英文对话 `pool.jsonl`；**`(bi)`** 使用与灵枢 `corpus567.jsonl` 同源的中英双语结构化字段（identity/time/summary/terms/en-text）。
   - 入库耗时反映各系统的真实入库方式：`dsh-dream` 构造内存 `Lesson` 对象并在首次检索时惰性填充 `WeakMap` 词频缓存（因此首次缓存构建计入查询耗时）；`Okapi BM25` 与 `Char-2gram` 在入库阶段预建全量内存索引；灵枢 `MdCGOS` 在入库阶段落盘 Markdown 与索引并 `flush()`，查询阶段走只读内存缓存。
3. **各评测集的真实定位**：
   - `bench6-100-zh-en`（137 轮）与 `locomo-zh-500`（567 轮）属于**低干扰标准问答检索上界**；
   - `memory-bench-1000`（1,000 条，含 40% 真实噪声）检验**高噪声信噪比与延迟**；
   - `dsh-agent-eval-40`（40 个编码 Agent 场景）检验**作用域隔离、版本/平台条件门控、证据防火墙、防幻觉与预算纪律**——这是纯向量/词法检索库默认不具备、但编码 Agent 生产环境最关键的能力。

核心提效来源（全部为通用 IR 与安全工程改造，**零外部运行时依赖**，无任何针对评测集的硬编码特判）：
- 零依赖混合 **BM25F** 多字段评分（覆盖 `title / when / action / prevents / problemKey / rationale / files / read-verified evidence`）；
- `WeakMap` 引用校验的每经验压缩倒排词频缓存 + 缓存过期时间戳（含 `files` 内容键失效校验，消除每查询重复 NFC 规范化、重复 `Date.parse` 与 8 字段重复探测）；
- 英文词边界匹配 + 轻量确定性词形还原（含 3 字母词根隔离命名空间 `3:fix`/`3:log`/`3:bug`/`3:run`，避免 `Tim`/`time`、`car`/`care` 误碰撞）+ `camelCase / PascalCase / snake_case / path` 标识符拆分 + 内嵌中文技术词独立概念化与双语同义桥接（软权重 `0.78`）+ 概念覆盖率 / 邻近短语加权 + 多概念强命中下的弱噪声尾部剪枝；
- 加固脱敏正则：覆盖 Bearer / `Authorization: Basic`、PEM 私钥、Postgres/Redis/HTTPS 连接串凭据、引号包裹 JSON/`.env`（含带空格口令）、前缀环境变量（`DB_PASSWORD`/`JWT_SECRET`/`ACCESS_TOKEN`）、URL 查询参数（保留后续 `&page=2`）、`hf_` / `npm_` / `AIza`、全角绕过字符与 `src/` 前缀高熵令牌绕过拦截，同时保护 `disk-space-*`、`task-*`、TypeScript 类型声明（`password: string`）、各类长工作区路径以及 `dream_save` 日记正文中的合法 Dream 引用 ID（`lsn_*`）零误杀。

- **纯英文精确首位召回**：在**零神经嵌入、零外部依赖**的前提下，`dsh-dream (raw-en)` 拿到 **`73.0% hit@1 / 0.7898 MRR`**，较 `v0.19.3` 提升 `+13.0%`，首位命中率追平 Letta Archival (`73.0%`)、超过 Vector RAG (`71.0%`) 与 Mem0 (`68.0%`)，并大幅领先灵枢 (`47%–54%`) 与图谱类记忆插件 (`18%–46%`)。

- **明确短板（绝不回避）**：

  2. 在**纯英文语料下直接用纯中文提问**（`raw-en` 查 `zh`），无多语言向量嵌入时 `dsh-dream` 仅有 `21.0%`（依赖中英技术桥接词与专有名词），无法替代双语嵌入模型做开放域跨语种问答。

## 4. 评测三：`memory-bench-1000`（1,000 条真实生产噪声池）+ 密钥脱敏审计

数据构成：250 `signal`（真实对话）+ 400 `noise`（测试夹具与系统演练日志）+ 350 `unlabeled`（边界校验记录）。全部在本机以相同 250 条信号查询（前 40 字符真实回忆前缀，`k=5`）串行实测：

| 系统（全部本机实跑） | `hit@1` | `hit@5` | `MRR` | `SigP@5` ↑ | `Noise@5` ↓ | 入库耗时 | 250 查询耗时 |
|---|---:|---:|---:|---:|---:|---:|---:|
| **`dsh-dream` 优化版** | **98.8%** | 99.6% | 0.9913 | 95.1% | 1.1% | **3.1 ms** | **634.9 ms** |
| `dsh-dream v0.19.3` 基线 | 98.0% | 99.6% | 0.9880 | 96.2% | 0.6% | 5.7 ms | 6,414.3 ms |
| **灵枢 Lingshu (`lexical`)** | 98.4% | **100.0%** | **0.9920** | **98.6%** | **0.2%** | 4,615.5 ms | 6,817.5 ms |
| **灵枢 Lingshu (`rrf4`)** | 98.0% | **100.0%** | 0.9900 | **98.6%** | **0.2%** | 4,615.5 ms | 6,809.6 ms |
| **灵枢 Lingshu (`rrf5+fuzzy`)** | 98.0% | **100.0%** | 0.9900 | 98.0% | **0.2%** | 4,615.5 ms | 15,964.4 ms |

**诚实对比分析**：
- `dsh-dream` 优化版拿下全场最高的 **`98.8% hit@1`**，在多概念强命中弱噪声尾部剪枝后，`SigP@5` 达到 **`95.1%`**、`Noise@5` 压低至 **`1.1%`**（远低于纯 BM25 的 `2.7%` 与 Char-2gram 的 `1.7%`）；250 查询耗时 `634.9 ms`（比自身 `v0.19.3` 快 **`10.1×`**，比灵枢查询阶段快 **`10.7×–25.1×`**），端到端（入库 + 查询）总耗时 `638.0 ms`（相比灵枢 `11,425.1–20,579.9 ms` 快 **`17.9×–32.3×`**）。
- **灵枢的真实优势**：在 `SigP@5 (98.6%)` 与 `Noise@5 (0.2%)` 上，灵枢表现更优——因为 `memory-bench-1000` 来自灵枢自身生产库且保留了 `importance` 元数据，同时灵枢对尾部弱匹配采取了更激进的截断策略（更少填满全部 5 槽位）。
