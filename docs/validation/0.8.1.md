# Dream 0.8.1 acceptance / 验收

## Observed failure

With the official 0.2.1-alpha.1 DeepSeek adapter and `deepseek-flash`, a short invented CSV preference with an encoding exception consumed all 1200 output tokens. The adapter returned `max-tokens` after reasoning and incomplete JSON. Dream correctly discarded it, but the useful candidate was lost.

## Change

The auxiliary extraction checks the official `llm.resolveModelInfo(provider, model, signal)` capability. If this exact model advertises the `off` reasoning effort, only the auxiliary call requests it. Unknown models, unavailable metadata and legacy hosts retain their provider default. Metadata resolution and streaming share the existing timeout and abort signal. No retries, larger budgets or main-agent settings were added.

## Validation

- Windows: 304 tests, 303 passed, one optional stress test skipped. Regression cases cover complete extraction within the short budget, unsupported/missing metadata, and metadata calls that ignore abort.
- Real official SDK/provider with the local existing API credential: the invented CSV preference was saved as one unreviewed, project-scoped candidate with its exact source and UTF-8 exception; a second case without reusable information saved nothing. Both finished with `stop`; project AGENTS.md and the credential file remained unchanged.
- The quality check uses invented session events, not a claim that those events were emitted by a human's live session. The previous 0.8.0 acceptance separately exercised complete official RC2 and Alpha AgentLoops using a scripted adapter.
- The user's native Desktop process and one main window were observed. The window was minimized, so it was not restored while the user watched a video. Native visual/interaction acceptance remains untested.
